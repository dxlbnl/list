# Conventions

Recurring patterns and rules that apply across the entire codebase. An agent should read this before writing any code.

→ See also: [AGENTS](../AGENTS.md) | [Client Modules](client-modules.md) | [Bits UI Styling](../components/bits-ui-styling.md)

---

## CSS

- All component styles live inside `<style>` → `:global { ... }`. This is **required** to prevent the Svelte compiler from stripping styles that target portaled/DnD elements rendered outside the component tree.
- Classes are manually namespaced to avoid collisions: `.list-group-item-row`, `.user-menu-container`, `.share-qr-image`, etc.
- Portaled elements (dialogs, DnD drag ghost `#dnd-action-dragged-el`) require top-level `:global` selectors.
- Design tokens come from `app.css`. Never hardcode colours or spacing values; always use `var(--token)`.

Key tokens: `--bg-0..3`, `--fg-0..3`, `--border`, `--border-hover`, `--accent`, `--accent-muted`, `--danger`, `--danger-muted`, `--success`, `--space-1..12`, `--radius-sm/md/lg`, `--shadow-sm/md/lg/xl`, `--font-mono`.

## Group Names

| Stored as | Displayed as | Notes |
|---|---|---|
| `""` (empty string) | `GENERAL` | Default group; items with no explicit group |
| `"My Group"` | `MY GROUP` | Arbitrary user-defined names |

**Rule**: Always convert between display name and stored name at the boundary. `actions.ts` handles this on write. The `[slug]` page converts `"GENERAL"` → `""` before calling actions.

## Slug Routing

Lists are addressed by `slug` in the URL, not by `id`.

- Slugs are generated by `slugify()` in `src/lib/utils.ts`.
- Reserved slugs (`login`, `api`, `settings`, `confirm`, `list`, `favicon`, `robots`, `static`, `app`) are blocked and get a random suffix appended.
- Slug collisions within a user's own lists also get a random suffix.
- **Shared lists** that collide with an owned list use a disambiguated slug: `{slug}--{userId[0..8]}`.
- The `+page.ts` load function resolves the URL slug → `listId` by calling `GET /api/lists`.

## Mutations

**Rule**: Components must never call `db.*` directly. All writes go through `src/lib/client/actions.ts`.

Rationale: `actions.ts` guarantees that every write is (1) immediately reflected in Dexie, (2) queued for sync, and (3) triggers an immediate sync attempt. Bypassing it breaks all three guarantees.

The one exception is `UserMenu.svelte`'s logout handler, which calls `dexieDb.delete()` to wipe the entire local database — this is intentional and not a mutation in the normal sense.

**Warning**: Reusable components in `src/lib/components/ui/` should never import `db`. If they need data, it should be passed as props. Only route-level components (in `src/routes/`) should use `liveQuery` or direct DB reads.

## Logging

- Use `logger` from `$lib/logger` everywhere. Never use `console.log` directly.
- Create child loggers for modules that produce many entries: `logger.child({ module: 'client-sync' })`.
- On the server, always call `await logger.flush()` before the function returns (required for Vercel serverless to ship logs to Axiom before freezing).
- Log levels: `debug` (suppressed in production), `info`, `warn`, `error`.
- `error()` accepts an optional third argument for the raw `Error` object, which extracts `message` and (in dev) `stack`.

## Auth Tiers

| Tier | How obtained | Notes |
|---|---|---|
| Anonymous | Automatic on first visit | `createAnonymousSession()` in hooks. Lists belong to the anonymous user ID. |
| Registered | Email magic link | The anonymous user record is merged into (or becomes) the registered user. All owned lists are preserved. |
| Shared | `list_users` join row | Any user (anonymous or registered) can be added to a list via an invite link. |

## IDs

All entity IDs (`user.id`, `list.id`, `item.id`, `session.id`) are generated with `nanoid()` (re-exported from `src/lib/utils.ts`). Never use `crypto.randomUUID()` or `Math.random()` for entity IDs.
